# STT and network-node foundations

The course adds a guided path from the staff reporting task through transport, network services, authorized access, application information and a bounded recovery handoff. It is reachable from Courses or the mission homepage. It is deliberately a public-source foundation with editorial teaching, not an approved operator/maintainer course, validated equipment emulator or qualification.

## Six lessons and separate practice

1. Start with the staff task: node versus transport roles and a receiving-user outcome.
2. Terminal indications versus accepted transport: explain what remains unverified without inventing terminal procedures.
3. Path reachability versus DNS: distinguish a supplied address-based test from a separate name lookup; do not bypass identity/certificate checks.
4. Authorized access: separate reachability, authentication, authorization and applicable supporting-service evidence.
5. Application freshness: distinguish an open local display from current remote information and independent unresolved dependencies.
6. Recovery handoff: repeat the user exchange after the last change and brief only its verified scope.

Each lesson contains an observable outcome, causal explanation, staff impact, conceptual dependency checks, fictional observation, a first-choice checkpoint with per-option feedback, and instructor discussion. Course progress stays in memory across learning areas. Reload/reset clears active answers. Recording the complete six-question result saves only the existing bounded activity/score/total/time summary; it does not infer completion of practical work. First choices cannot be overwritten during an attempt.

The three course capstone buttons start the matching existing handoff, synchronization or dual-fault lane. Starting a capstone resets any active lane, as disclosed in the UI. Guided course checks and lane debriefs are separate formative evidence. Connected instructor accounts do not receive these local results automatically; no backend grading endpoint or database migration is added.

## Printable instructor packet

The web edition generates self-contained HTML with lesson content, answer explanations, capstone tasks, observation criteria, source metadata and manual gaps. It opens offline and can be printed or saved through browser Print. All interpolated text is escaped, and the packet uses a restrictive CSP with no script or external assets. The packet is transparent teaching material, not a protected examination. Any displayed guided score is editable and self-reported; it establishes no instructor approval or practical performance.

Native users can read the curriculum and observation guide on screen. No filesystem permission or native export capability is added.

## References and remaining work

The retrieved 2016 Army WIN-T overview supports historical JNN/BnCPN/STT roles. The current public at-the-halt program search summary supplies modernization context, but direct access returned 403; the limitation remains visible and no fielding timeline is treated as proof of a unit's baseline. Retrieved Microsoft DNS and Kerberos guidance supports vendor concept education only, not a claim about the installed Army software.

Exact variants, public operator/maintainer manuals, software/firmware baselines, interface documents, authorized safety/access procedures and qualified human review remain necessary for deeper equipment-specific instruction. The course does not provide frequency, key, fill or cryptographic-device operating procedures. There are no operational-text inputs, external AI calls or automatic uploads.

The publication gate checks six distinct outcomes, bounded content, permitted source origins, retrieval limitations, answer structure, manual gaps, instructor criteria and resolvable capstone IDs. It cannot grant technical approval.

## Validation

Model tests cover first-choice locks, incomplete/invalid/forged answers, inherited-property score inflation, safe packet text and separation from practical assessment. Browser checks cover all six lessons offline, wrong-first-choice scoring, navigation continuity, summary-only history, packet rendering/accessibility, correct capstone routing, reset/reload, mobile layout and keyboard focus. Existing source/content, backend, browser, connected learning, security, database, container and native build checks remain required. Automated accessibility checks do not replace assistive-technology user testing or technical review.
