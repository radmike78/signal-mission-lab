# Mission-to-practice continuity

The learning brief now suggests a bounded practice focus and explains why it is relevant. The selection is an editorial learning aid, not an equipment recommendation, diagnosed fault, documented interface or operational dependency model.

- Explicit satellite-transport study topics suggest the generic transport-acceptance exercise. In a mixed satellite/node study list, this focus comes first so learners can rehearse acceptance before downstream service tests. It does not supply a satellite acquisition or lock procedure.
- Explicit transport-node/routing study topics, or a distributed training setting without a satellite topic, suggest the routing/tunnel reasoning exercise.
- Other descriptions fall back to a generic build/dependency example with an explicit notice that no system-specific match is established. This is not an identity-access lesson. A dedicated identity/service case remains future work.

Only validated enum/catalog choices determine the suggestion. No raw mission text is passed to practice, sent to a server or added to storage. Echelon does not allocate equipment or change this study-routing heuristic.

The practice screen includes a compact handoff notice and a return action. Returning preserves the mounted mission view, its synthetic requirement observations and preparation selections. Reopening the same mission practice resumes the active guided case. Selecting another case clears the mission notice to avoid presenting the manual choice as the recommendation. Starting independent practice from My training also clears it. Reloading clears active views; completed formative history remains governed by the existing 50-record store and erase controls.

Tests cover mixed-topic precedence, supported routing inputs, generic fallback boundaries, invalid identifiers, and offline browser handoffs for all three focuses. They verify that the brief and active check survive a round trip and that changing cases removes stale context. These checks establish application behavior only; qualified technical review and learner-outcome validation remain required.
