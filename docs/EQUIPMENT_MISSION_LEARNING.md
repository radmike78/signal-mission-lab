# Equipment understanding and mission impact

Equipment (formerly labeled Knowledge graph) is now a primary navigation area. STT, JNN, CPN, BCCS, TSI, JBC-P, MMC-S, TRILOS, SINCGARS and HF have purpose, mission use, setup dependencies, configuration rationale, possible failure effects, remaining-service checks and user-task recovery validation.

Each lesson offers COMMEX, STAFFEX, WFX and mission rehearsal tasks. These are editorial training designs, not prescribed exercise definitions. Public references support purpose/context; variant procedures and technical/instructor review remain pending. Existing fault guides and manual gaps remain available.

The leader-update practice requires six fields: evidence/failure, affected users, disrupted task, verified remaining capability, recovery/help/decision, and restoration uncertainty/next update. Text stays in React memory only, resets on equipment or exercise changes, and is never sent to an API or saved in browser history. Use synthetic content only. The review is a six-item self/instructor discussion rubric, not automated semantic grading or readiness certification.

Four formative assessment questions cover bounded outage reporting, stale information, staff validation of recovery and honest restoration estimates. Existing local assessment scoring includes these questions. No connected instructor database schema changes are required.

Validation: Python content/reference checks, existing Node model tests, TypeScript/build, and browser journeys. The equipment mission browser check covers draft completeness, editing, rubric reset, equipment/exercise reset, mobile layout and offline use.
